# Initial passive connector candidates

Research date: 2026-10-15. Status: candidate selection research, not a tested integration catalog.

This note updates the earlier [OSINT ecosystem review](https://github.com/TheDarkSkyXD/OSINT-AI-Spider/issues/3) and [SpiderFoot review](https://github.com/TheDarkSkyXD/OSINT-AI-Spider/issues/2) with first-party access and licensing constraints. No target lookups, scans, credential setup, or integration tests were performed. Placement recommendations below are product judgments, not claims of provider approval.

## Proposed shortlist

Use the following 23 candidates as the passive-source and processing portion of the initial catalog. Add the separately researched bug-bounty adapters and core file/browser capabilities to reach the approved 25 to 40 entry launch target. Count one adapter once, even when it has several endpoint actions. Do not count individual Sherlock sites or every GitHub API endpoint as separate Connectors.

"Bundled candidate" means suitable to evaluate for distribution with the app. "Verified candidate" means an optional maintainer-managed adapter requiring credentials, another runtime, or additional terms review. Neither label means verification has passed. A conditional candidate must resolve its stated blocker before release.

| Candidate | Purpose and proposed placement | Evidence and constraint that changes the decision |
| --- | --- | --- |
| RSS and Atom reader | Bundled candidate. User-selected news, government, and organization feeds. | [RSS specification](https://www.rssboard.org/rss-specification) and [Atom RFC](https://www.rfc-editor.org/rfc/rfc4287) define syndication formats. A format standard grants no reuse rights to a publisher's articles or images. Record the feed URL and distinguish item links/snippets from full content. |
| Internet Archive Wayback | Bundled candidate. Find existing captures through Availability and bounded CDX queries. | The [official API page](https://archive.org/help/wayback_api.php) documents Availability, Memento, and CDX. Availability can return no accessible capture. Preserve capture time separately from retrieval time. Keep Save Page Now as a separate action because it requests new collection. Archive access is not a blanket content redistribution license. |
| Brave Search API | Conditional Verified candidate. Web/news discovery with user credentials. | [Terms updated 1 Sep 2026](https://api-dashboard.search.brave.com/documentation/resources/terms-of-service) restrict storage beyond transient operation, redistribution, derivative uses, and AI model improvement. Its [official FAQ](https://brave.com/search/api/) explicitly allows plans with storage rights to grant permissions beyond those general terms. Verify the selected plan/order form for Case retention and sharing; a generic API key or paid plan is insufficient evidence. |
| Wikidata | Bundled candidate. Public entity identifiers, aliases, and referenced relationships. | [Data access documentation](https://www.wikidata.org/wiki/Wikidata:Data_access) describes CC0 data, entity retrieval, query services, User-Agent etiquette, and backoff. Preserve references and revisions where available; statements are leads rather than identity or legal conclusions. Linked articles and media have their own rights. |
| Sherlock | Verified candidate. Bounded public username-presence checks through a Python worker. | The [MIT-licensed project](https://github.com/sherlock-project/sherlock) checks candidate profiles across sites. Review each enabled site's method and terms. Same username does not establish common ownership. Maintain a small healthy site allowlist rather than enabling the complete database automatically. |
| libphonenumber | Bundled candidate. Offline number parsing, formatting, and plausibility validation. | The [Google library](https://github.com/google/libphonenumber) is Apache-2.0. Number format and numbering-plan metadata do not establish the subscriber, present carrier, or live location. Select and pin the actual supported JavaScript package during implementation. |
| DNS resolution | Bundled candidate. Bounded typed record queries using the configured resolver. | [Google's DoH documentation](https://developers.google.com/speed/public-dns/docs/doh) documents a possible resolver interface, not an exclusive dependency recommendation. Show the resolver receiving the query. Ordinary DNS queries can reach authoritative servers and must not be described as zero-contact historical passive DNS. No brute-force enumeration in this adapter. |
| Domain RDAP | Bundled candidate. Authoritative domain registration metadata. | [IANA's RDAP bootstrap registry](https://www.iana.org/assignments/rdap-dns) maps TLDs to servers. Bootstrap routing does not unify registry terms, redaction rules, authentication, or quotas. Preserve authoritative endpoint and redacted/missing fields. Do not advertise private registrant discovery. |
| IP and ASN RDAP | Bundled candidate. Network allocation, organization, and abuse-contact metadata. | [ARIN's RDAP documentation](https://www.arin.net/resources/registry/whois/rdap/) describes registration access. Route to the appropriate regional registry rather than treating ARIN as universal. A network allocation does not establish the identity of the person operating an endpoint. |
| crt.sh certificate search | Conditional Verified candidate. Historical certificate-name discovery. | The [operator's repository](https://github.com/crtsh/certwatch_db) publishes database schema and code. This research did not establish a supported, versioned JSON API contract, quota agreement, or availability commitment. Resolve supported access and bounded query behavior before launch; certificates do not prove current ownership or reachability. |
| GitHub public research | Bundled no-auth candidate with an optional credentialed Verified mode. Public repositories, profiles, issues, releases, commits, and supported search. | [REST limits](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api) distinguish public unauthenticated and authenticated access, endpoint-specific search limits, and secondary throttles. [Search documentation](https://docs.github.com/en/rest/search/search?apiVersion=2022-11-28) defines endpoint limitations. Preserve repository, commit/revision, and license; public visibility does not remove repository content rights. Do not promise exhaustive code search. |
| Mozilla Readability | Bundled candidate. Extract readable text and metadata from already obtained HTML. | The [Apache-2.0 library](https://github.com/mozilla/readability) recommends keeping DOM script execution and resource loading disabled and sanitizing output. It is a processor, not a crawler or permission to copy content. Retain the original capture alongside derived text. |
| Tesseract | Verified candidate. OCR of supplied images through an isolated local/runtime worker. | The [official manual](https://tesseract-ocr.github.io/tessdoc/) identifies Apache-2.0 licensing, native builds, and trained-data dependencies. Language packs and platform binaries require explicit packaging choices. Record OCR output as a derivative with engine/language version, not exact source text. |
| Apache Tika | Verified candidate. Document type detection, metadata, and text extraction. | [Apache's project page](https://tika.apache.org/) documents the Java runtime and release branches; 2.x is end of life. Pin a currently supported version and inspect its dependency licenses. Parse untrusted documents in a restricted worker with size/time limits. Do not ship an old Java 8 stack for convenience. |
| ExifRead | Verified candidate. Extract image metadata in the optional Python worker. | The [BSD-3-Clause project](https://github.com/ianare/exif-py) is pure Python. Preserve raw tags and units; metadata can be removed or edited and does not prove capture location or date. Offline processing does not need an external provider account. |
| GLEIF | Bundled candidate. LEI entity reference data and reported relationships. | [LEI data terms](https://www.gleif.org/en/meta/lei-data-terms-of-use) provide free access to LEI reference data under CC0. LEI coverage is not a complete company registry. Retain relationship exceptions and reporting dates instead of inferring undisclosed beneficial owners. |
| SEC EDGAR | Bundled candidate. US public-filer submissions and XBRL data. | [Official API documentation](https://www.sec.gov/search-filings/edgar-application-programming-interfaces) requires no API key, links automated-access policy, and states that data.sec.gov does not support CORS. Web uses an approved execution path, such as the local runtime, attached Runner, or managed service; Electron can use its compatible runtime. Configure declared User-Agent and source-wide pacing before enabling. Preserve reporting period, filing date, and amended facts. |
| UK Companies House | Verified candidate. Official company, officer, filing, and control records where exposed by the API. | [Authentication documentation](https://developer.company-information.service.gov.uk/authentication) requires application credentials. [Rate guidance](https://developer-specs.company-information.service.gov.uk/guides/rateLimiting) states 600 requests per five minutes per application. Company records describe filed information, not independently established truth. Treat document/image retrieval rights and endpoints separately. |
| OpenCorporates | Conditional Verified candidate. Cross-jurisdiction company discovery. | [Licensing](https://opencorporates.com/legal/licence/) distinguishes permitted share-alike keys from paid non-share-alike access. [Enterprise terms](https://opencorporates.com/legal-information/enterprise-api-terms-of-service/) distinguish internal use from external distribution. Private Cases, team sharing, and exports need rights matching those operations; open-source app code alone does not satisfy open-data sharing conditions. |
| OpenSanctions | Conditional Verified candidate. Referenced sanctions and financial-risk records. | [Current licensing page](https://www.opensanctions.org/licensing/) distinguishes query-priced screening API, internal screening licenses, and reseller redistribution licenses. Do not bundle bulk data or assume a screening subscription permits redistribution. Matching a name is a candidate match for review, not an accusation or confirmed identity. |
| VirusTotal existing reports | Conditional Verified candidate. Hash, URL, domain, and IP report lookup with an appropriate entitlement. | [Official API restrictions](https://docs.virustotal.com/reference/public-vs-premium-api) prohibit Public API use in commercial products/services and certain business workflows. User-provided free credentials do not remove this restriction. Keep file/URL submission out of the default lookup adapter because submission discloses material and can trigger new analysis. |
| Shodan existing intelligence | Verified candidate. Query existing host/search records with user credentials and entitlements. | The [official API](https://developer.shodan.io/api) includes both database lookup and scan-submission operations. Expose only selected read endpoints here. Scan credits and query credits are different; requesting a fresh scan belongs to the separate authorized active capability. Historical records do not establish current exposure. |
| URLhaus | Conditional Verified candidate. Existing malware-URL intelligence, without payload downloads. | The [current Community API page](https://urlhaus.abuse.ch/api/) requires an Auth-Key and says commercial or for-profit needs may require its paid commercial API. This is no longer a safe no-auth/default assumption. Keep account-specific feed URLs out of logs, citations, and exports. |

Maigret is an alternative to Sherlock, not an additional launch requirement. Its [current repository](https://github.com/soxoj/maigret) distinguishes MIT-licensed code from a separately maintained private site database and commercial API. Choose one username engine initially and test the actual enabled site definitions. Do not infer thousands of working integrations from its advertised site count.

## Decisions this research supports

1. Bundle small offline processors and stable no-auth adapters only after packaging and behavior checks. Credentialed mode can use a different catalog placement from the same provider's no-auth mode.
2. Distinguish third-party historical intelligence, ordinary DNS, direct HTTP retrieval, external submissions, and active testing. Calling all of them "passive" conceals network behavior that affects case scope and provider costs.
3. Store a provider-policy reference with each adapter. Retention, AI processing, team display, and export are separate permissions. Provider search snippets and the independently retrieved source page may have different rights.
4. Treat commercial entitlement as unresolved until the exact account contract covers the planned operation. This affects Brave, VirusTotal, OpenCorporates, OpenSanctions, and URLhaus in particular.
5. Publish supported inputs, enabled actions, runtime requirements, source date, and failure behavior. Each adapter still needs format fixtures, live health checks, pagination/backoff checks, and provenance verification before it can earn a shipped verification label.

## Remaining evidence gaps

The first-party GLEIF API documentation endpoint could not be fetched by the research browser; its data terms were accessible. Validate its endpoint contract separately. crt.sh access support and rate expectations need operator documentation or agreement. This note does not select OTX because its current API and commercial reuse contract were not established during this pass. No source policy or provider contract was negotiated.

## Search-provider alternatives

Brave's FAQ links the general terms above and expressly distinguishes special storage-rights plans. The plan/order form is therefore the material selection evidence. This pass did not establish a separate AI-specific agreement granting every intended Case operation.

[Exa's published terms](https://exa.ai/terms) cover its API as well as its search engine. Additional customer agreements can override general terms, but section 4.2 restricts copying, downloads, distribution, and derivative uses except where expressly permitted. These terms do not provide a clear general grant for permanent shared Case evidence. Treat Exa as a conditional alternative pending the applicable API agreement, not a confirmed solution to Brave's storage restriction.

[Tavily's terms](https://www.tavily.com/terms) permit API integration with Customer Applications for internal business purposes. They distinguish Output from the Services, but also contain AI-functionality input/output processing and training provisions. This pass did not establish an express general right covering retained evidence, external Case sharing, and exports for this product. Obtain the applicable agreement before selecting it for sensitive Cases.

Recommendation: support a replaceable search adapter and choose a launch provider only after verifying the actual storage, sharing, export, and input-processing terms. No default commercial search provider is established by this research. Direct source URLs, user-selected feeds, and official public APIs still support useful research while that choice remains open.
